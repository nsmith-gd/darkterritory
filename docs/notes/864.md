864. **The Windows CI flake: Game.Tests' host left running after its tests pass (nathaniel1 n1-w3, queue #591).**
   - Claimed 2026-10-19 17:00 UTC by n1-w3 at the Token Budget Manager's ask.
   - **What it is:** the message is xunit.v3's (`xunit.v3.mtp-v2`, `TestPlatformTestFramework`): once the run returns, a thread-pool
     item waits 1 s, prints "Waiting 10 seconds for foreground threads to exit...", waits `shutdownForegroundThreadWaitSeconds`
     (10) more and, if the process is still there, prints the fatal line and `Environment.Exit(1)`. So the host took more than
     11 s to exit after its last test: a managed foreground thread still running, or a `ProcessExit` handler or shutdown step
     that slow. (On Windows, once `ExitProcess` starts, the watchdog's own thread is gone: the runtime hadn't got there.)
   - **Reproduced** (19 Oct, a temporary `Flake 591` workflow on `claude/n1w3-591-flake`: the whole suite as CI runs it, four
     windows-latest runners, twice each, run 39294502225): one fire in eight, in **DarkTerritory.Sim.Tests**, not Game.Tests.
     Sim.Tests has no native code at all (no audio device, no OpenXR, no Vulkan), so the OpenXR loader's errors beside the
     first sighting were only beside it: they're Game.Tests' own stderr, printed whenever that host fails.
   - **What's left running at the end** (a probe, `dotnet-stack report` on Game.Tests' own process as its assembly fixture
     disposes, in every one of the eight): the main thread waiting on the run, the thread pool, xunit's message bus, and
     `Microsoft.ApplicationInsights.Channel.InMemoryTransmitter.Runner`: the test platform's telemetry
     (Microsoft.Testing.Extensions.Telemetry 2.4.0, through xunit.v3.mtp-v2). No thread of the game's.
   - **Why that holds the host** (decompiled): the platform's `AppInsightsProvider.Dispose` waits 3 s for its telemetry task
     and cancels it, but the task's `finally` flushes the ApplicationInsights client, and disposing its `InMemoryTransmitter`
     flushes again; both are `Flush(default)`, a synchronous HTTP send whose default timeout is 100 s
     (`Transmission.DefaultTimeout`). A runner slow to reach the telemetry endpoint keeps the host in that send past xunit's
     1 + 10 s, whichever test project it is, and xunit forces it out with exit code 1.
   - **The fix under test:** the test platform's telemetry opted out where the tests run (`TESTINGPLATFORM_TELEMETRY_OPTOUT=1`,
     with `DOTNET_CLI_TELEMETRY_OPTOUT=1`), so there's nothing to flush.
