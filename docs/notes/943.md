943. **Playtest telemetry: the PostHog sink behind #626's upload interface (queue #637; the director's backend answer, 20 Oct, inbox `nathaniel3-tbm-telemetry-backend`: PostHog; follows note 919; n1-A1, nathaniel1).**
    - **What it is:** `PostHogTelemetryUpload` (`DarkTerritory.Game/Telemetry/PostHogUpload.cs`), an `ITelemetryUpload` (note
      919). It sends a batch of the spool's finished sessions to PostHog's batch capture endpoint, `POST {host}/batch/`.
      - **Events:** each session line becomes one event, `dt_<type>` (`dt_session`, `dt_night`, `dt_minute`, `dt_death`, …),
        whose properties are the line's fields (note 913's schema).
      - **Who:** `distinct_id` is the session line's anonymous install id (#625; the session id if there's none).
        `$process_person_profile` is false, so PostHog makes no person profiles. `session` carries the session id.
      - **When:** the lines carry only a session clock (`t`), not wall time. An event's `timestamp` is the session's start,
        reckoned as when its file was last written less its last line's `t`, plus the line's own `t`.
      - **Requests:** at most `eventsPerRequest` (500) events each, so a batch goes in as many requests as it needs.
      - **Answers:** 2xx is sent (the uploader marks the sessions `.sent`). 429, 408, 5xx, a timeout (`timeoutSeconds`, 20)
        or no network is retried with the uploader's backoff. Any other 4xx, such as a wrong key, is refused for this
        launch.
    - **The settings:** `content/tuning/telemetry.json`'s `upload.postHog`: `on`, `host` (`https://us.i.posthog.com`; EU or
      self-hosted works too, https only), `projectKey`, `eventsPerRequest`, `timeoutSeconds`.
      - The project key is PostHog's write-only project API key. It can add events and read nothing, so it's no secret in a
        client (note 907); nothing else is held.
      - **It ships with an empty key.** With no key, `TelemetryUploader.NetworkSinkFor` makes no sink and nothing is sent.
        The director makes the PostHog project, and the key goes into `projectKey`, or into a playtest build's copy of
        `telemetry.json`.
    - **In the app:** the uploader, with #625's consent gate, is pumped in the background, one send at a time:
      - at launch, which sends the earlier launches' sessions;
      - after each night ends.
      - It is never pumped during a night. Without consent it sends nothing.
      - This launch's own session is still being written, so it goes at the next launch (sent while open, it'd go twice).
      - The `file` sink beside a problem report (note 919) is unchanged.
    - **Headless:** `dt telemetry send [--dir d] [--dry-run]`. `--dry-run` (or no key) prints the endpoint, the masked key,
      the sessions, events and requests that would go, and the first three events. Without it, it sends.
    - **Pinned by** `PostHogUploadTests` (4), against a fake PostHog (`HttpMessageHandler`):
      - no key, no sink, and the game ships without one;
      - plain http is never a sink;
      - each line is an event under the install id, with no person profile, split by `eventsPerRequest`, a minute apart
        where the lines are;
      - 5xx, 429 or no network is retried, a 401 or a blank key is refused;
      - nothing goes without consent, what goes is marked sent, and the open session waits.
