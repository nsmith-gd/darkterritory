450. **Public and private runs, the password, and the run's mood (N1, queue #186; the director, 8 Oct 2026: "We should do public and private matches. List of games available to join should always list Ping. Private matches should be password gated. We should have a setting called 'Here for Laughs' that hosts and joiners can toggle that will automatically sort lowest ping, here for laughs servers ... We should do the same for a setting called 'Feeling Competitive' so players can find servers that have players who want to go for the longest runs they can").** Note 169's PRIVATE wasn't listed at all, and anyone with the address got in.
    - **A private run is listed with a lock** (the director's answer to "should private runs show up in the list?": "Listed with a lock"). On the host screen, VISIBILITY: PRIVATE adds a PASSWORD field (`Settings.LobbyPassword`, remembered). OPEN THE LOBBY is greyed until one is typed. The run goes on the LAN beacon and into the Steam search like a public one, with `locked` "1" in its lobby (`NetPlaySession.LockedKey`; the beacon's twelfth field). The join list draws a padlock before its name (`BitmapFont.Lock`, the font's `char lock` on U+E000, since the padlock's own code point doesn't fit in a `char`). Picking it opens the password page (`Screen.Password`), which starts typing at once: the page is only for that. Enter joins.
    - **The host checks it, in the Hello (protocol 43).** The Hello carries the password's key after the outfit: SHA-256 of a fixed prefix and the password, trimmed and upper-cased (`Messages.PasswordKey`). The typed words never go on the wire, into the lobby's values or into the host's memory, and a password read out over voice is typed the same in any case. `HostSession.PasswordKey` set, a new joiner whose key doesn't match (compared in fixed time) is refused `RefusalReason.Password`, "WRONG PASSWORD", in the greeting line before it takes a place. So a guess fills nothing and never shuts a full lobby. The joiner's game throws `JoinRefusedException`, and the app puts the password page back up with WRONG PASSWORD over it and the words as typed. `HostSession.WrongPasswords` counts them.
    - **Who gets in without it.** A held place's token (note 253): they were let in once. The host's own player and its bots, which send the key like anyone. The host's **Steam friends**, the way an invite would let them in (`HostSession.Trusted`: the peer came in over `OnlineTransport` and `IOnlineBackend.IsFriend` says so; Steam's `HasFriend` with `k_EFriendFlagImmediate`, `FakeOnline.Befriend` in tests). A LAN or address joiner has no account to be a friend by, so they type it.
    - **The host is told.** Its lobby panel says "PRIVATE: LISTED WITH A LOCK, JOINED WITH THE PASSWORD" (`LinkInfo.Locked`), where a public run's says its game's listed. Found running the app as two machines (below).
    - **The ping, always.** Every row has its ping column filled: the measured or estimated figure, or "-- MS" until there is one (note 169 left it blank).
    - **The run's mood: one setting, `Settings.Mood`**, EITHER, HERE FOR LAUGHS or FEELING COMPETITIVE (`RunMood`), the MOOD row on both the host and join screens. Hosting, it's said in the listing (`mood` in the lobby, the beacon's thirteenth field: "laughs", "competitive", or "" for either) and shown in the list's MOOD column (LAUGHS, COMPETE, -). Joining, `ListedGame.Sort` puts runs of your mood first, then the rest, each nearest first (unmeasured last). Looking for either keeps note 169's nearest first. The director's "a setting called 'Here for Laughs'" and "a setting called 'Feeling Competitive'" are one three-way setting, not two toggles, because a run can't be both and one setting keeps a host's run and their own search agreeing. It's a sort, not a filter: the list stays whole. The join screen's MOOD row sits under the list, so the nearest run is still what's selected as the screen opens.
    - **The command line:** `--password words` hosts a private run, listed and locked, and joins one with `--join address --password words` (or `+connect_lobby`). `--mood laughs|competitive`. `--private` without a password is note 169's unlisted, friends-only run, as it was. The console's log of a failed start prints the launch with its password starred (`Launch.Redacted`).
    - **Verified:** `PrivateRunTests` (Sim: the key; only the right password, in any case, gets in; the refused take no place; an open run ignores a password; a trusted friend; a dropped crewmate back on their token after the run's locked). `LobbyBrowserTests.APrivateRunOnThePlatformIsListedLockedAndLetsInThePasswordOrAFriend` (the fake Steam: listed locked with its mood and ping; the words in no lobby value; WRONG PASSWORD twice, then in with the password; the host's friend in without it) and `...OnTheNetworkIsListedLockedAndAskedForItsPassword` (the beacon over loopback). `FrontEndTests.TheJoinListPutsRunsOfYourMoodFirstAndALockedRunAsksItsPassword` and `APrivateRunNeedsAPasswordToOpen`. `dt screenshot --menu join [--mood laughs|competitive]`, `--menu host --private`, `--menu password [--wrong]`.
    - **Two machines, virtually:** the app run twice under xvfb in two Linux network namespaces joined by a veth pair (10.77.0.1 hosting `--host 27450 --password lantern --mood laughs`, 10.77.0.2 joining). The joiner's namespace heard the beacon over the wire, on this protocol, locked and laughs, with no password in it; `--join` without the password was refused WRONG PASSWORD; with "LANTERN" it boarded, 2 aboard. Its ping read 3,167 ms: each copy reads the network once a frame, and both were drawing on the CPU at about one frame in five seconds, so the figure was the frame time, not the link. Steam's half (the relayed datagrams, lobbies, invites, friends let in) still needs Steam clients on real machines: the cloud sessions have no Steam client or account and Steam's hosts are blocked there.
    - **Not yet:** a host can't change the password or the mood once the lobby's open (it's set as the run's hosted). A password guesser isn't slowed down, beyond each guess being a new connection and a refusal. "The longest runs they can" is only what the host says of the run; nothing yet lists a crew's record distance beside it.
