   **#624 T1, the session recorder.**
   - A `Telemetry` recorder in `DarkTerritory.Game` (presentation side), never in `DarkTerritory.Sim`. It reads the
     Sim's state and events, and never changes them, so determinism and `NetcodeTests` are untouched.
   - Each machine records its own session: the host its night as the host sees it, a client what its player saw and did.
   - One versioned event schema (`schema` field, JSON lines), written down in the note and pinned by a test. What it
     records:
     - **Session:** build and commit, edition, OS, GPU, the graphics settings, PC or VR, the crew's humans and bots,
       host or client, route and tier, cars.
     - **The night:** km run, stops made, deaths (cause, place on the line, minute), encounters (the `EncounterLog`'s
       records, kind and outcome), incidents, cars lost, cargo delivered, how it ended, minutes played, quits and
       disconnects (where and when).
     - **Roles and economy:** jobs taken and for how long, scrip earned and spent, purchases.
     - **UX friction:** time to first move, time to first job, cards and prompts shown against acted on, rebinds,
       the menus opened and how long they stay open.
     - **Health:** `FrameWatch`'s hitches, the frame-time percentiles, ping and loss.
   - Sampled at a bounded rate (counters and per-minute rollups, events only for things that happen a few times a night),
     so a 45-minute night stays well under 1 MB.
   - `dt telemetry record` (or a `--telemetry` flag on `dt playthrough`/`dt harness`) writes a bot night's session, so
     the recorder is verifiable headless.

   **#625 T2, consent and privacy.**
   - **Opt-in, asked once on first run**, and changeable in Settings at any time. Off means nothing is recorded.
   - **Anonymous:** a random install id, never a name, Steam id, IP, email, hardware serial or anything typed. No voice,
     no chat text, no player names (the crew is counted, not named).
   - **A "what we collect" page** in Settings, in plain words, listing every field T1 records.
   - **Delete:** a button that clears the local spool and, once T3 uploads, asks the server to delete the id's data.
   - **Retention** stated on the page (the director's call; 12 months is a sensible default).
   - The studio is in Quebec: Law 25 (consent, a person in charge of privacy, a privacy notice), PIPEDA, and GDPR for
     European testers. Opt-in and anonymous keeps this simple; the wording is the director's to approve.
   - Dev builds may default to on for the director's own nights (said on the first-run screen).

   **#626 T3, the spool and the upload.**
   - A local spool: JSON lines under the player's data folder, capped (oldest dropped first), one file a session.
   - A pluggable sink: `file` first (the spool is the data; a tester sends it with the problem-report flow, note 452),
     `https` later.
   - **No secrets in the client.** At most a write-only ingest key that can add events and read nothing. Never the
     feedback branch's GitHub token (note 516 is a dev-only path).
   - Uploads in the background between nights, never during one, with retry and a size cap.
   - **The backend is the director's call** (asked in the inbox): a small self-hosted ingest the studio runs, a hosted
     product analytics service (PostHog, GameAnalytics' REST API), or no upload at all for now (testers send their
     spool files).

   **#627 T4, `dt telemetry` and the dashboard.**
   - `dt telemetry summary <dir>`: sessions, nights, minutes, how nights end, quit points, deaths by cause and by minute,
     encounters by kind, funnel steps (launch, first night, first job, first stop, first delivery, a second night).
   - `dt telemetry map <session>`: deaths and quits along the night's route (the `linegen` map).
   - A playtest dashboard (an artifact the director opens) from the summary's JSON.
   - Feeds the spawn director overhaul's balance work (note 874, #613): real crews' encounters per night against the
     brief's targets.
   - Starts now on synthetic sessions from bot nights (T1's headless path), so it is ready when real data comes in.

   **#628 T5, the playtest kit.**
   - An end-of-night survey: three 1–5 questions (fun, fear, would play again) and an optional comment, skippable. Its
     answers go in the session.
   - Cohort codes: a playtest code typed or in the build, so sessions group by test.
   - A playtest build channel (a `--playtest` edition of `tools/package.sh`, telemetry consent asked up front).
   - With the player's consent: a night's replay (note 515) and crash reports (note 452) attached to the session.

   **Rules every item keeps:**

   - Nothing recorded or sent before consent. No personal data.
   - The schema is versioned, written down in the note, and pinned by a test.
   - Every item is verifiable headless (`dt telemetry`, tests).
   - Stays clear of the spawn director overhaul's files (`Director.cs`, `enemies.json`; note 874). T1 only reads
     `EncounterLog`.
