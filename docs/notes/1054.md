1054. **A joiner buys at the forge (n1-F1, nathaniel1's Token Budget Manager's worker; queue #752; GDD §3.1 "Not yet", §11; notes 697, 1027; note 1050 rank 4).** *In review.* Before this, a joiner at the town's blacksmith was told "The host keeps the crew's scrip: ask the host to buy it". The director plays two-player nights with a guest, so the guest could look at the shelves and buy nothing.
   - **The message** (protocol **95**, REVIEW.md N3; 94 went to the crew's tools, note 1052, merged first). Two new reliable messages (`Net/Messages.cs`):
     - `Order` (28), client → host: a done flag, then an upgrade id (empty when done). It is intent only (REVIEW.md N1): the joiner names what it wants and changes no state of its own.
     - `OrderAnswer` (29), host → the joiner who ordered: the id, bought or not, the words the host's own menu would say, the crew's scrip after it, and whether the crew owns the upgrade now. The answer doesn't carry the whole upgrades list, because a crew owning most of the 76-line catalogue wouldn't fit one datagram. A livery chosen again stays owned and goes to the end of the list, as `Campaign.LiveryOf` reads it. A developer build's free shelves can take one off.
   - **The flow.**
     1. The joiner's catalogue opens as before (the host's setup's scrip, cars and upgrades), but `CanBuy` now holds for a joiner too.
     2. A choice calls `FrontEnd.SmithyOrder` → `NetPlaySession.Order` → `ClientSession.Order`. The joiner sees "Tender capacity: ordered. The host pays from the crew's scrip."
     3. The host's `HostSession` queues each order as it arrives (bots' are dropped). Every frame, the app calls `NetPlaySession.ServeOrders`, which buys each order in turn with the same purchase the host's own forge menu makes: `Campaign.BuyUpgrade` (the dev unlock where on), paid from the crew's shared wallet (GDD §11), saved at once, with a telemetry purchase. The host's `FrontEnd.SmithyBuy` is now this purchase plus "refit when the menu shuts". Each answer's words are `FrontEnd.SmithyWords`, the function the host's menu itself uses, so a refusal reads exactly as the host would see it ("Tender capacity costs 260 scrip; you have 130", "you already have Tender capacity").
     4. The joiner's `FrontEnd.SmithyAnswered` shows the words. On a purchase it also updates the shop's scrip and shelves, so the line reads OWNED and the purse is right.
     5. When the joiner shuts the shop after ordering, `SmithyDone` sends a done `Order`. If the host bought anything for that joiner, `ServeOrders` returns true, and the host does note 697's refit as soon as it isn't in a menu of its own (if it is, its own refit takes it when the menu shuts). The refit is the existing path: `CarryOn`, then the yard hosted again with the campaign's upgrades. Every joiner follows it (`Following.Refit`), so the upgrade is fitted on every machine.
   - **Two at once.** Orders are bought in the order the host's transport delivered them. Two joiners ordering the last of something in the same tick get one purchase and one refusal in the host's words, and the crew is charged once.
   - **Not a campaign night** (the host has no crew's scrip). Every order is refused with `NetPlaySession.NoPurse`.
   - **Determinism.** Nothing here is sim state. The wallet is the host machine's campaign (spec E), the order is a session message like Kick, and purchases are applied in arrival order on the host only. The train changes only through the refit's new setup, which every machine builds the same way, as before.
   - **Not done.** A joiner's word to the blacksmith to scrape the train (note 1039) still says to ask the host. The same `Order` could carry it as a reserved id when someone wants it.
   - **How to check.**
     - `dotnet test --project tests/DarkTerritory.Game.Tests -- --filter-class DarkTerritory.Game.Tests.JoinerForgeTests`, which covers:
       - an order bought, charged once and fitted on both machines through the refit and follow;
       - a refusal (too little scrip, owned already, not a campaign night) costing nothing, in the host's words;
       - two joiners ordering the last one at once;
       - the messages read back as written.
     - `dt forge order --joiners 2 --ids tenderCapacity,radioRange --scrip 900`: joiner 2 is charged 520 for both, joiner 3 is told "you already have …" for each, and the yard is to be refitted.
     - In the app, host a campaign night, join it from a second machine, walk the joiner to the blacksmith, buy, then press DONE. Both machines go back into the yard with the upgrade fitted.
