### The mic behaviours: what they read

Not sim state as such: the client's own voice leveller (`Ballast.Voice.VoiceLeveller`) already puts each player's speech
level on **every intent** as `PlayerIntent.Voice` (a byte, 0–255; the Choir, the Moose and the draw read it, World.cs and
Moose.cs). Because it's intent, it's on the host and on every predicting client alike, so a trait kept from it is
deterministic (rule: clients send intent, never state). The host keeps, per player, a rolling share of the last 120–180 s
with `Voice ≥ TalkingAbove` (40, the Moose's and the Choir's threshold):

- `voice.quiet`: under 5% of the last 180 s, while another living crewmate is in earshot or on the radio.
- `voice.loud`: over 60% of the last 120 s.

Exemptions, which need one new bit: a player **with no microphone**, or with voice off in the settings, is never
`voice.quiet` (the hello carries it: a protocol bump, COORDINATION rule 10); push-to-talk counts only while held, which
reads as quiet, so the threshold is a share, not a silence; a **solo** game and a crew of bots-and-one never mark
anybody; bots set `Voice` already (`Bots.cs`, the Choir's chatter), so they answer both. **Only the level** is read: no
audio is kept or sent, nothing past the night (note 907's privacy rule).
