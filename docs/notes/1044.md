   - **`REVIEW.md`** (the repo's root) is what a reviewer checks a PR against: a person, Claude Code Review, or the workflow below. It turns CLAUDE.md's Rules and the lessons the notes paid for into one checkable line each, with what breaks it in a diff, under ids a finding cites:
     - **D** determinism (wall clock, unseeded RNG, container order, Windows and Linux alike, moving frames);
     - **N** networking (intent not state, the host decides, `Protocol.Version` to main's + 1 at merge, COORDINATION rule 10);
     - **T** numbers (in `content/tuning`, pinned numbers moved with `SpecTableTests` and the spec, creature numbers through the Creature Tweaker, unapproved work behind a flag);
     - **P** platform and build (Sim without platform deps, dev tools only under `#if DEVTOOLS` with no `#else`, everything authored is text, warnings and `dotnet format`);
     - **V** verifiable headless (a test or a `dt` path, screenshots looked at, tells never drowned, tests not loosened to get green, CI's 16 GB with two test projects at once (notes 804, 1043), the perf budget);
     - **W** workflows (least privilege, no secrets to a fork's code, runner time not doubled) and **C** coordination (claimed, done when merged, the note, the log, other owners asked, a "how to check" line).
   - **Risk tiers by path**, with what each needs before merging: **high** (Sim and Net, the wire, save and record formats, workflows and packaging, player-build gating) a test that fails without the change, netcode, replay and crossplay green on the merged head, `actionlint` for a workflow, an owner's look; **medium** (Game, render, audio, App, `content/`) a screenshot or the review packet for what's seen, `dt audio render` for what's heard, the spec for a number; **low** (docs, other tools, the CLI, Dev, tests) a clean build and the coord check. Blocking findings are D, N, P2, V4, W1 and a missing tier requirement; the rest are suggestions.
   - **Why a file of its own:** Claude Code Review reads `REVIEW.md` beside CLAUDE.md on its own, so the simplest cross-review is already there for any repo with it installed: nothing to build. CLAUDE.md says what to do; REVIEW.md says how to see it not done, which is what a reviewer needs and CLAUDE.md is too long to be.
   - **The workflow** (`.github/workflows/cross-review.yml`, script `tools/review/cross_model.py`): on each pull request (opened, pushed, reopened, out of draft) a second model reads the diff against REVIEW.md and keeps **one** comment up to date (found by its `<!-- cross-model-review -->` marker): the tier, blocking findings, suggestions, what it couldn't check.
     - **Off until switched on:** without the `ANTHROPIC_API_KEY` secret it does nothing and says so as a notice on the run.
     - **Never blocks:** the job is `continue-on-error`, the script exits 0 whatever happens (an API failure becomes the comment), and it isn't a required check.
     - **Least privilege:** `contents: read`, `pull-requests: write` (the comment), nothing else; `persist-credentials: false`.
     - **No secrets to a fork:** a fork's PR is skipped (and `pull_request` gives it none anyway; never `pull_request_target`). The script and REVIEW.md are checked out from the **base** commit, not the PR's head, and the diff comes from the API, so no PR's code runs with the key and no PR rewrites its own reviewer.
     - **The model:** the repo variable `CROSS_REVIEW_MODEL`, default `claude-opus-5-5`, effort high, streamed, server-side refusal fallback (`fallbacks: "default"`). Most PRs here are written by Opus 5.5; set `CROSS_REVIEW_MODEL=claude-fable-5-1` for a reviewer that isn't the author's model (dearer). Generated and binary paths (`content/art/`, `content/audio/`, images, sounds, models) are left out and named in the comment; a diff past 600k characters (about 150k tokens) or one GitHub won't give (300 files, 20,000 lines) is said to be too large rather than read in part.
     - **Cost:** one request per push to a non-draft PR, the in-flight one cancelled by a newer push. At a few hundred PRs a week, mostly small, expect a few dollars a day on Opus 5.5.
   - **To switch it on (the director):** add the repository secret `ANTHROPIC_API_KEY` (Settings > Secrets and variables > Actions > New repository secret), an API key from console.anthropic.com. Optionally the repository variable `CROSS_REVIEW_MODEL`. Don't make "Cross-model review" a required check. To have Claude Code Review use the rubric too, switch Code Review on for this repository (its setup is in the Claude Code docs, code.claude.com, under Code Review); it picks REVIEW.md up by itself.
   - **How to check:**
     - `actionlint .github/workflows/cross-review.yml` (clean; `pip install actionlint-py`).
     - Offline: `env -u ANTHROPIC_API_KEY python3 tools/review/cross_model.py --diff some.diff --rubric REVIEW.md` writes the comment it would post, the failure in it (exit 0); `--no-diff "why"` the too-large comment.
     - On GitHub: this PR's run shows the notice "Cross-model review is off" until the secret is set; with it, the PR gets one comment, updated (not added to) on the next push.
