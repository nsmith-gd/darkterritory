896. **Epic Online Services P2P: the third online platform, for players off Steam (n1-N1, queue #274; the netcode audit's gap 6; note 24).** The director, the inbox, 20 Oct (`nathaniel1-tbm-non-steam-relay`): **eos**. The itch.io build could join only by address with an open port. Now, without Steam, the game signs in to Epic Online Services by device id (no Epic account for anyone, no launcher), hosts a lobby there, and friends join it by a **join code** the host reads out (six letters and digits that can't be misread, shown `K7Q-M2X`); the game then runs over EOS P2P, straight to the host when NAT allows and through **Epic's relays when it doesn't**. Free of charge, no servers of ours. It is a third `IOnlineBackend` (`Ballast.Online/Eos/EosBackend.cs`), beside `SteamBackend` and `FakeOnline`, whose carrier is the third `IDatagramCarrier`: the game's protocol, sessions, rejoin (note 253), crew cap (note 254) and private runs (note 450) are the same game on the wire.

**How it's built.** `IEosSdk` is the part of the EOS SDK the game uses, in EOS's own terms (string product user ids and lobby ids; every request answered in a callback inside a later `Tick`). `EosBackend` maps it onto `IOnlineBackend` and the new `IJoinCodes`: ids hashed to the game's `UserId`/`LobbyId` (FNV-1a, the same on every machine) and mapped back; a member attribute `name` for each member (device-id users have no name anyone else can read); the lobby's values gathered into one `UpdateLobby` per frame (EOS rate-limits them), the owner reading its own at once as on Steam; a join by id searched first, so a shut or full lobby says so and its values are there to read (note 254's "CREW FULL"); connection requests accepted only from lobby-mates, held until they arrive, as on Steam. The EOS SDK isn't thread-safe, so everything it's asked happens in `Poll`, on the game's thread; the carrier only queues packets for it (a transport's pump thread can use it). `FakeEos` is the in-process EOS the tests and `dt harness --eos` run on: NAT types (two strict, or strict and moderate, can't meet directly), relay control (allow, force, none), packets from a peer not yet accepted held and let through on accepting (EOS's delayed delivery), lobbies with limits and permission levels, searches by attribute or by id, invites. `EpicSdk` is the binding to Epic's own C# wrapper, compiled only when `external/eos/` holds the SDK (`EOS_SDK`).

**What EOS can't do without Epic accounts, and what stands in.** No friends list: `IsFriend` is false, so a private run asks everyone its password (on Steam the host's friends skip it). No overlay: F2 does nothing on EOS, and the host's status line says `code K7Q-M2X` where Steam's says `F2 invites`. No ping estimates: the browser's ping column is blank for EOS lobbies. Every EOS lobby is advertised to EOS (a join code is a search), and the game's own `public` value keeps friends-only ones off its list, as the Steam path's filter does; anyone with the code can join a friends-only run, as anyone with its address can. A typed code goes where an address goes on the join screen (`--join K7Q-M2X` too); a LAN host name of exactly six code letters is read as a code when EOS is up (add `:port`).

**The credentials** (product, sandbox, deployment, client id and secret) never go in the repository: `eos.json` beside the game, written by the Release workflow from its secrets (`EOS_PRODUCT_ID` …), or the `DT_EOS_*` variables on a developer's machine. `EOS_SDK_URL` is the SDK, as `STEAM_REDIST_URL` is Valve's library (external/eos/README.md, tools/store/README.md).

**Flag.** `relay` in eos.json (`DT_EOS_RELAY`): `allow` (default: the director's words, "the relay when NAT blocks a direct path"), `force` (always the relays: nobody's IP address reaches anybody, as on Steam), `none`. The director's call is asked (below).

**What isn't there yet: the real SDK.** The EOS SDK can't be fetched in the agents' containers (the Epic Developer Portal, dev.epicgames.com, is refused by the proxy; Epic publishes no NuGet package, and its licence lets the game ship Epic's native libraries but not us republish the SDK). So `EpicSdk.cs` is written against the SDK's documented C# API and has **never been compiled**: the first build with `external/eos/` filled is its first compile, and it may need small fixes there (a renamed member, a nullable). Result codes and enum values are matched by name, so most such renames fall through to `Other` rather than breaking the build.
